# 书籍归档

## 找对书库，先分清请求

用户指定的管理库优先；未指定时，本机约定入口是 `/Volumes/ArchivedDocuments/书库索引.md`，指向同卷的 `Books/`。挂载缺失、入口冲突或管理文件不齐，就报告缺什么；不要新建一个空 `Books`，也不要回退到下载目录。以下命令均从**已确认的 Books 根目录**执行，只用该库自带的 `00_书库指南/书库工具.py`，不运行来书中的脚本。

先读库根 `AGENTS.md` 和 `00_书库指南/分类规则.md`。实际叶子分类查 `主题目录.json`，既有归属查 `书目.csv`，写入时间与哈希查 `文件指纹.csv`。这些文件在盘上是准本，不在 skill 中另存一份分类表。

| 用户要什么 | 做到哪里为止 |
|---|---|
| 查一本书或找旧路径 | 查书目；若已改名，查 `00_书库指南/迁移记录/` 的旧新路径对照。不移动或登记。 |
| 只做方案／只核对 | 不移动、不登记。要求不落盘时用 `check`，不要带会写报告的 `--log`。 |
| 整理新书 | 按下列顺序处理 `01_待入库/` 或用户明确点名的批次。不要借机重排旧库。 |
| 只重建索引 | 运行 `python3 00_书库指南/书库工具.py index`。若与手写索引冲突，保留原件并报告，不删除后重试。 |

## 一批新书的操作顺序

1. **先核对，再移动。** 运行 `python3 00_书库指南/书库工具.py check --log`。退出码 `0` 是无差异，`1` 是发现差异，`2` 是未完成。投放口本批的“新增”本来就会返回 `1`，可继续；已有书缺失、大小或指纹改变、仅时间改变要分别报告，不把它们当作本批新书。`2` 时先排障。怀疑内容被替换、尤其大小和时间仍相同时，用 `check --full --log`；仅有旧 SHA-256 的文件能这样证明内容是否相同。检查不等于接受变化，也不是后台监控。
2. **给作品而非文件选位置。** 先用书名、作者、ISBN、外文名查旧书，有同一作品就沿用其主类；没有才根据版权页、目录和正文判断“读者用这本书解决的主要问题”，选一个已有叶子。教数据库但用 Python 举例，归数据库，不归 Python。格式、语言、来源、阅读进度和拆书候选都不是第二个主类。
3. **拟定路径并保留命名证据。** 单一文件可直接放叶子；同书多格式、译本和配套材料放一个书名目录。只有编号或乱码时，有书内证据才改名，保留原扩展名、版本、卷号、样章信息。无法确认就保留原名放 `01_待入库/待辨识/`，记录疑点，不登记到猜测的正式分类。
4. **留对照，再同卷移动。** 写入该库 `00_书库指南/迁移记录/<本批>/`：原相对路径、目标相对路径、字节数、原 `mtime_ns`（可另列 UTC）、改名依据。对每个目标使用不覆盖的移动方式；同名先区分版本，必要时加 `〔同名02〕`，即便哈希一样也不擅删。整包保留代码、音频、离线网页资产和 Git 仓库的相对结构。跨卷先不移除源件；需要迁移已登记旧路径时单列方案，普通 `register` 不是迁移旧指纹的命令。
5. **只登记已归位的新文件或书包。** 直接用下面的命令；三个变量分别是这本书实际的相对路径、已有叶子路径和核实书名。已有书名目录新增格式时可登记整个书包。登记会记录大小、文件最后写入时间（UTC 与 `mtime_ns`）和支持类型的 SHA-256，并更新书目与分级索引；不必紧接着再跑一遍 `index`。整理时间另记，不能用它替代原写入时间。

   ```sh
   python3 00_书库指南/书库工具.py register "$relative_path" --分类 "$leaf" --书名 "$title"
   ```

6. **验收后再报完成。** 核对新路径确有原文件、书目主类唯一、指纹行与原大小和时间相符，并从 `书库索引.md` 经分类 `索引.md` 抽查一条链接能到书。再做一次 `check --log`，只允许已解释的差异；未辨识件或旧异常不要报成零差异。命令中断时先分别查书目、指纹和索引已经写到了哪一步，避免盲目重跑。卷根的 `书库索引.md` 是入口，不是分类生成器的覆盖目标。

交付时说清：本批归档和改名数量、留待辨识或需确认的项目、是否发现旧书变化，以及总索引和本批记录的位置。除非另有明确要求，不下载、上传、导入研习系统，也不安装定时任务。
