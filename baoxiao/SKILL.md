# baoxiao — 报销发票整理与凑金额

把 `D:\work\报销` 根目录的 PDF 和图片发票一起按目标报销金额凑单，移动到当月月报目录。

## 目录约定（写死）

- 发票池：`D:\work\报销` 根目录直属的 PDF 和图片（JPG/JPEG、PNG、WebP 等，扩展名不分大小写）
- 月报目录：`D:\work\报销\YYYYMM_月报`（如 `202609_月报`；不存在则创建。历史目录有 `—`/`——` 等混用，新目录统一用 `YYYYMM_月报`）
- **月报目录由用户指令给出**（如「移到 202609_月报」）；用户没提供时**必须主动问清归到哪个月报**，不要默认猜当月——报销月份常与自然月不一致（实例：2026-10-13 整理的是 202609 月报）。

## 铁律：只用根目录的发票

**候选池 = 根目录直属的 PDF 和图片，绝不递归子目录。** 两种格式是同一个池，不按格式分别凑单；同一发票号的 PDF、照片或截图只计一次。 `太少/`、`taptap/`、历史 `YYYYMM_*` 等子目录里的发票全都不靠谱（用户 2026-10-13 明令），凑不够金额时也不许把它们列为补充候选或主动建议——如实报告差额，等用户补充新发票。

## 流程

1. **列候选**：运行 `python .claude/skills/baoxiao/scripts/match_invoices.py <目标金额>`，一次列出根目录的 PDF 和图片。只要还有待核对图片，不要根据 PDF 小计判断够不够，也不要移动。
2. **核对票面**：
   - **PDF**：脚本用 `pdftotext` 提取。标「低置信/未验证」或金额冲突时，看正文的价税合计行；可用 `--reviewed "文件名=金额"` 传入核实值。
   - **图片**：逐张看原图的「价税合计（小写）」，可用「金额合计 + 税额合计」复核。文件名可能带多个金额，不能据此定价。看不清就索要清晰图，不猜、不跳过。
   - 按发票号核对是否重复；已确认是重复副本或非发票的图片，用 `--reviewed "文件名=skip"` 排除，保留原文件。不能仅因金额相同就判重。
3. **混合凑单**：每张图片用一个 `--reviewed` 传回核对结果，与 PDF 一起按分选「≥目标且超出最少」的组合。例如：
   ```bash
   python .claude/skills/baoxiao/scripts/match_invoices.py <目标金额> --reviewed "餐饮.jpg=128.50" --reviewed "同票截图.png=skip" --move "<月报目录>"
   ```
4. **移动纪律**：
   - 凑到 ≥目标：**默认直接 `--move`**（用户 2026-10-15 定版：移动是默认动作，不必先展示组合等确认）；图片保持原格式移动；文件名金额与票面不符时按票面金额修正文件名。
   - **全部合计也不够：什么都不移**，报告最大可达金额与差额，等用户决策。
5. **汇报**：移动文件清单、各张金额、合计、与目标的差值。

## pdftotext 解析要点（脚本已封装，人工复核时用）

- 电子发票文本层中文常乱码，但数字可靠；金额一律以正文为准。
- 「合计」行形态是 `金额 价税合计` 两个小数一行（¥ 可能丢失），取后者。
- 用 `金额 + 税额 = 价税合计` 交叉验证；多行明细可能凑出干扰数字对（如实付+优惠=原价），所以取文档中最后一个通过验证的合计行（合计在票据底部），并优先采信与文件名金额一致的值。
- **多明细带折扣发票（青庖等连锁餐饮）的陷阱**：文本层尾部结构是 `税额 金额` 汇总行 → `价税合计`**单独一行** → **税率分组小计段**。小计段的明细数字对会偶然通过交叉验证（验证只要求税额存在于全文任意数字中），「取最后一个验证对」会锚到小计/税额（2026-10-15 实例：把税额 15.16 当总价，实际 268.28）。
- 脚本提取值与文件名金额大幅不符时，**先怀疑脚本误读而非文件名**（当日 4/4 张全是脚本错）：真实价税合计常以单独数字行出现、不被「两个小数一行」模式捕获；文件名金额作为独立数字在正文出现即可采信。
