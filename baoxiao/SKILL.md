# baoxiao — 报销发票整理与凑金额

把 `D:\work\报销` 根目录的发票 PDF 按目标报销金额凑单，移动到当月月报目录。

## 目录约定（写死）

- 发票池：`D:\work\报销` 根目录直属的 PDF
- 月报目录：`D:\work\报销\YYYYMM_月报`（如 `202609_月报`；不存在则创建。历史目录有 `—`/`——` 等混用，新目录统一用 `YYYYMM_月报`）
- **月报目录由用户指令给出**（如「移到 202609_月报」）；用户没提供时**必须主动问清归到哪个月报**，不要默认猜当月——报销月份常与自然月不一致（实例：2026-10-13 整理的是 202609 月报）。

## 铁律：只用根目录的发票

**候选池 = 根目录直属 PDF，绝不递归子目录。** `太少/`、`taptap/`、历史 `YYYYMM_*` 等子目录里的发票全都不靠谱（用户 2026-10-13 明令），凑不够金额时也不许把它们列为补充候选或主动建议——如实报告差额，等用户补充新发票。

## 流程

1. **列候选**：发票池根目录的 `*.pdf`。
2. **凑金额**：运行
   ```bash
   python .claude/skills/baoxiao/scripts/match_invoices.py <目标金额>
   ```
   脚本逐张提取价税合计并交叉验证，穷举子集和给出「≥目标且超出最少」的组合；加 `--move <月报目录>` 会直接移动并列出目标目录核实结果。
3. **核对置信度**：脚本对每张票标注依据。标「低置信/未验证」的发票，移动前用 `pdftotext <file> -` 人工看一眼合计行。文件名金额只是参考，一切以 PDF 正文提取为准。
4. **移动纪律**：
   - 凑到 ≥目标：用户指令里已要求移动时直接 `--move`；否则先展示组合再移。
   - **全部合计也不够：什么都不移**，报告最大可达金额与差额，等用户决策。
5. **汇报**：移动文件清单、各张金额、合计、与目标的差值。

## pdftotext 解析要点（脚本已封装，人工复核时用）

- 电子发票文本层中文常乱码，但数字可靠；金额一律以正文为准。
- 「合计」行形态是 `金额 价税合计` 两个小数一行（¥ 可能丢失），取后者。
- 用 `金额 + 税额 = 价税合计` 交叉验证；多行明细可能凑出干扰数字对（如实付+优惠=原价），所以取文档中最后一个通过验证的合计行（合计在票据底部），并优先采信与文件名金额一致的值。
