# 《救一笔！》 / save_one_stroke

## 定位与入口

- 源码仓库：<https://github.com/slb1988/save_one_stroke.git>，与 skills 仓库独立，不把游戏源码或关卡拷进 skill。
- 本机定位提示：`D:/Github/save_one_stroke`；其他机器按仓库 URL 定位实际检出目录，不把本机路径当部署路径。
- 公网试玩：<https://game.luckeyhome.site/>。
- 本地预览：在游戏仓库执行 `npm start`，默认 <http://localhost:4173/>；命令与端口若有变化，以该版本 `package.json` / 项目说明为准。
- 直达单关的试玩链接：`<预览地址>#level=<URL 编码后的关卡路径>`，如 `http://localhost:4173/#level=course%2F01-reach-the-ground`（路径中的 `/` 需编码为 `%2F`，编码形态若与目标版本路由实现不一致以代码为准）。交付关卡批次时用此格式给出可试玩入口。

游戏技术基线为纯静态 HTML/CSS/JS 与本地 Matter.js 0.20。Node 用于本地开发、工具与验证，不要求生产环境运行 Node 服务；实际依赖以目标版本为准。

## 工作分流

- **做关卡、生成 JSON、修改物理规则**：读 [关卡创作与验证](level-authoring.md)，再到游戏仓库读取同版本的权威格式与 fixtures。
- **发布或回滚**：读 [VPS 发布](deployment.md)，交由 VPS agent 在其业务上下文执行。
- **只讨论创意与试玩反馈**：沿主 skill 的轻量闭环处理，不必加载发布细节。

## 玩法取向

优先考虑新规则和因果变化带来的惊喜，而不是单纯让空间更挤、墨水更少或绕障更繁琐。例如风向改变应让玩家重新理解受力或解题方法，而不只是增加操作精度要求。

提出创意时分别说清“已有规则内可做”与“需要新增机制”。临时支点、挂点、重力变化、落球冲击等设想是否可用，必须查目标版本的规则、实现和测试；不因为另一个任务正在开发就视为已支持或已上线。

## 权威版本

游戏规则与数据契约由源码仓库维护。GitHub 默认分支链接只是定位入口；处理指定 commit/tag 时，使用该 revision 对应的本地文件或将链接中的 `master` 换成实际 revision，不混用不同版本的文档与数据。

遇到未提交的并行改动，不将其归纳成稳定事实，也不改动不属于当前任务的文件。这里不记录当前发布 commit、关卡总数或开发流水账。
