# Jira 每日待办工作流

## 目标

生成“当前用户在指定 BigPicture Box 中今天应该推进什么”的事实快照与建议计划，并让同一天后续询问稳定复用同一份数据。

## 1. 输入解析

按以下优先级确定参数：

1. Box：命令行 `--box` → 用户 URL 中 `/box/<BOX_ID>/` → `.env` 的 `JIRA_BOX_ID`。
2. Jira 地址：命令行 `--base-url` → `.env` 的 `JIRA_BASE_URL` → 用户 URL 的 origin。
3. Token：进程环境变量 `JIRA_TOKEN` → 项目根 `.env`。

配置的 `JIRA_BASE_URL` 优先于用户 URL 中的 host。这样用户粘贴旧 LAN 地址时，仍可走本机配置的首选网络入口，只借 URL 提取 Box ID。

## 2. 每日缓存规则

缓存目录固定为 Skill 的 `assets/cache/`。文件按以下范围隔离：

- 本机日期
- Jira Base URL
- Box ID
- Token 的单向短指纹（只用于区分身份，不保存 Token）

“每天只拉取一次”指每天为同一范围生成一份 Jira 网络快照；一次快照内部可以调用 `myself`、字段发现、搜索等多个只读接口。

默认行为：

1. 当天缓存存在且可解析 → 使用缓存，不访问 Jira。
2. 当天缓存不存在 → 拉取并原子写入缓存。
3. `--refresh` → 用户明确要求后覆盖当天缓存。
4. `--offline` → 只允许缓存；不存在时直接报错。
5. 缓存损坏 → 非离线模式重新拉取，离线模式报错。

后续分析直接读缓存。记录 focus/assist 计划只修改缓存，不应触发第二次 Jira 拉取。

## 3. 查询口径

查询所有当前用户在 Box 中的工单，以便同时计算完成率和未完成项：

```jql
issue in box("<BOX_ID>") AND assignee = currentUser()
ORDER BY cf[<Rank field id>] ASC
```

未完成的权威判断是 `status.statusCategory.key != "done"`。不要使用 `resolution is EMPTY`，因为该 Jira 工作流中部分“完成”工单的 resolution 仍为空。

保留以下事实：

- Key、摘要、状态与状态分类
- Jira Rank、优先级、类型
- 原始/剩余估算和已登记工时
- 当前及历史 Sprint、跨 Sprint 次数
- 创建/更新时间、开始/结束/截止日期
- 经办人、报告人、标签、组件、版本
- 描述、最近评论、父子项和关联工单

## 4. 分析顺序

先处理“状态卫生”，再做排期：

1. **可快速关闭**：剩余估算为 0、已有完整工时、曾完成后回到处理中。
2. **正在推进**：近期更新、已有 CL/验证记录、状态为处理中。
3. **短平快**：半天到一天可完成，且验收边界明确。
4. **协作或阻塞**：有未完成关联项、他人评论、报告人与经办人不同，或需要他人验收。
5. **大块遗留**：跨多个 Sprint、估算较大、没有描述或验收标准；优先拆分或移出，不要机械塞进当天。

容量使用 Jira 的剩余秒数计算；默认 8 小时为 1 人日。将剩余人日与当前 Sprint 剩余工作日对比。超载时明确指出需要移出或拆分多少工作量。

## 5. 协作分析

只依据缓存中的证据判断，不臆测人员：

- `reporter != assignee`：报告人通常是需求或验收入口，可建议确认验收。
- 最近评论来自他人：引用评论所表达的依赖或建议。
- 存在未完成 issue link/subtask：列为明确依赖。
- 没有描述、关联项和他人评论：写“Jira 中没有明确协作对象”，再建议先补复现、验收标准或影响方。
- 自动机器人评论仅作为流水线/CL 证据，不当作协作人。

## 6. 用户当天计划

用户可能用序号引用最近一次报告，例如“今天处理 1、2，3 辅助看看”。

1. 先从本会话最近展示的表格解析序号对应的工单 Key。
2. `1、2` 写入 `daily_plan.focus`，`3` 写入 `daily_plan.assist`。
3. 若序号上下文不存在或存在歧义，先向用户确认，不要按 Jira Rank 猜测。
4. 后续报告优先展示已记录计划，但仍提示状态变化和阻塞风险。

## 7. 输出格式

```markdown
## Jira 今日待办

数据：<network/cache> · 拉取时间 <timestamp> · <Box/Sprint>

### 今日计划
- 主处理：<Key + 摘要>
- 辅助检查：<Key + 摘要 + 是否有明确协作对象>

### 当前待办
| 顺序 | 工单 | 状态 | 剩余 | 风险/下一步 |

### 容量与风险
- 完成数 / 总数
- 剩余人日 / Sprint 剩余工作日
- 跨 Sprint、WIP、日期/描述缺失

### 需要配合
- 只列有 Jira 证据的人员、依赖和建议动作
```

报告中的顺序是本次分析建议顺序，不等同于 Jira Rank。若重新排序，后续仍以工单 Key 识别已保存计划。

## 8. 序号落 Key 示例

若最近报告明确显示 `1 → PL-123`、`2 → PL-456`、`3 → PL-789`，用户说“处理 1、2，3 只辅助检查”时应保存：

- 主处理：`PL-123`、`PL-456`
- 辅助检查：`PL-789`

这只说明序号如何落到稳定 Key；每日计划以本机缓存里的 `daily_plan` 为准。
