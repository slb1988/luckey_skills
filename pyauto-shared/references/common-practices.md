# pyAutomation 共性知识与经验

本文件只定义跨系统边界；具体状态、授权、重试和恢复入口以领域文档及当前源码为准。

## 身份、状态与证据

- 业务对象 ID、业务轮次、job ID、外部 build/task ID、Agent 与 workspace 不是同一个身份。重试/刷新/提交 rename 后，旧日志可能仍在，先核映射再归因。
- 前端是 API 投影；API 快照是当前状态，活动流解释先后；外部系统决定外部副作用是否真实发生。单个绿色标签不能覆盖其他状态轴。
- 页面文案是归因结果，不是原始证据。追到生产该结论的分支与本轮输入；区分“真正命中”“证据缺失”“采集失败”和“模型/传输失败”。
- 时间先带上时区再比较。后端记录常为 UTC，构建日志可能为本地时区；排队、前置依赖等待、模型请求、工具执行与重试退避分别计时。
- 判断线上事实优先使用本轮 API/活动/日志/artifact，再看部署 revision、have/head、源码和文档；plans 与历史记忆仅提供假设。
- 错误摘要保留阶段、原始原因和证据来源；基础设施错误不伪装成模型认可或业务规则命中。

## 异步与外部副作用

- 请求被接受、任务入队、被 worker 领取、外部动作完成、DB 收敛和通知送达是不同阶段。HTTP 200 只证明该接口的约定，不代表后续任务完成。
- callback 必须核业务对象、当前代际与执行来源。迟到、重复或并发回调不能覆盖较新的结果；实现使用该模块既有的幂等/CAS/fence 契约。
- 多 worker 的 check-then-act 需要原子领取或事务约束；不要靠 UI 按钮禁用或一次查询假装串行。
- 外部系统与 DB 通常不在同一事务。外部动作可能已成功而 DB 未落库；结果未知时先只读对账，不盲重试不可逆动作。
- 重试/补偿属于领域策略。一次失败、transient、永久错误和 unknown 分开；一个系统可自动重试，不证明另一个系统也安全。
- 通知通常是辅助副作用，但是否回滚由具体模块契约决定。通知送达不能证明业务完成，也不能证明本地 watcher 已收口。
- callback 优先或有 fallback 不等于零模型调用；需要覆盖所有实际入口和回调缺失分支才能作此保证。

## 配置与部署事实

- 配置文件、交互 shell、服务进程及子进程的环境可以不同。查有效配置时只报告变量名、来源、是否设置和必要的非敏感值。
- 服务启动脚本 source 环境文件可能覆盖 PATH；npm/pnpm、venv、Pi/Node/Python 的实际解析路径要在真实服务账号下核对。
- 源码目录、受信工具根、被处理 workspace、cwd 与产物根分开。搬工具不应无意搬业务数据、规则根或运行账号状态。
- P4 `have/head/opened/shelf`、待提交修改、已提交代码、已部署版本、在途任务 snapshot 分栏核实；一次 sync 或源码默认值不能证明任务已采用新版本。
- API prefix 以服务的当前路由/Swagger 为准；前端页面 URL、反向代理前缀与 Flask namespace 不可机械互换。
- 重启前先查会产生外部副作用的在途任务，遵循部署 skill 的空闲/停机契约；不能靠旧 PID 文件证明进程身份。
- schema 变化按 [数据库迁移参考](../../auto-server-backend-deploy/references/database-migrations.md) 处理；脚本启动成功不证明数据库版本匹配。

## 所有权与执行边界

| 对象 | 入口 | 边界 |
|---|---|---|
| pyAutomation backend/frontend、DevOps helper、TeamCity DSL | `ws:autoserver-deveops` | 在该工作区读取现行模块文档及 VCS 状态 |
| 游戏业务代码、MainDev 规则与其工作区 | `ws:maindev` | 工具迁移不能推导业务规则也迁移；具体工具归属查领域接线 |
| Flask/数据库/Redis/TeamCity server/部署和服务日志 | `@auto-server` | 运行时只读取证；部署等变更需要明确授权 |
| 构建服务账号、实际 engine workspace、版本与本轮 artifact | 精确 WinBuilder agent | 精确名称先发现；A2A cwd 不一定是 TC workspace |

`ws:` 是项目位置，不是远程机器；`@agent` 是运行时入口，不是源码仓。用 `workspace_resolve` 解析真实路由，远工作区由 Orca worker 执行，不在协调者复制其项目上下文。

P4 两类工作区的字符集约定相反：DevOps depot 为 Unicode，CLI 使用项目要求的 `-C utf8`；MainDev 游戏 depot 为非 Unicode，不设 utf8。每次仍现场确认连接/用户/client，不能让步骤级参数污染另一个 depot 的进程。

A2A 本地等待中断不证明远端已停；保留任务身份查询原任务，避免重复派发。机器是否允许变更及超时恢复遵循其运行时契约，不把“只读”文字当作实际权限隔离。

## 验证与交付

1. 优先隔离探针：保留真实参数解析、状态机或协议，替换 DB/P4/HTTP/模型等外部副作用。先复现再最小修复。
2. 定向测试覆盖目标语义，尤其正确正例与本次误报反例；本地 fake 测试不等于真实 headless、网络、认证或部署验收。
3. 密钥只使用既有安全注入。异常/URL/子进程输出和 artifacts 同样可能泄露，脱敏不是只检查配置文件。
4. P4 改动按 depot 建专用 pending CL，收尾 `describe -s` 与 `opened` 确认仍受跟踪，不把用户/其他任务改动卷入。
5. 交付只需决定性结论、证据、修改位置、测试、变更编号与未验证/未授权边界；不默认生成长报告或额外评审。

长期文档用时态中立的机制描述；部署进度与一次性证据留给执行记录。遇到漂移先标范围，再由 owning workspace 核实，不能把修文档称为修生产。
