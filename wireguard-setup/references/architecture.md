## 配置三元组：NAT 转发的三个独立开关

WireGuard 服务端做 NAT 转发时，三个系统层的开关必须对齐。缺任意一个，客户端都 ping 不通其他设备。

```
┌─────────────────────────────────────────────────────┐
│ ① net.ipv4.ip_forward = 1         内核层            │
│    允许非本机目标的数据包跨接口转发                   │
├─────────────────────────────────────────────────────┤
│ ② iptables FORWARD -i wg0 -j ACCEPT  filter 表      │
│    允许从 wg0 进入的包穿过 forward 链                │
├─────────────────────────────────────────────────────┤
│ ③ iptables -t nat POSTROUTING -o eth0 -j MASQUERADE │
│    出站时改写源 IP 为 eth0 地址（SNAT）              │
└─────────────────────────────────────────────────────┘
```

| 缺失哪一层 | 现象 |
|-----------|------|
| 缺 ① | 包在到达内核后被丢弃，客户端完全无法访问外部 |
| 缺 ② | 包能转发但不能跨接口，客户端之间无法互通 |
| 缺 ③ | 包能出去但回不来（对端不认识 10.77.77.x），只能 ping 服务器 |

## AllowedIPs 的双重语义

WireGuard 是无状态协议，每个 peer 的密钥绑定到一组允许的 IP 范围。
`AllowedIPs` 同时承载两个职责：

| 角色 | 含义 | 示例 |
|------|------|------|
| 路由表 | 哪些目标 IP 的包发送给这个 peer | `0.0.0.0/0` = 全隧道 |
| 访问控制 | 这个 peer 发来的包里，源 IP 必须在 AllowdIPs 范围内 | `10.77.77.2/32` = 只接受 .2 |

这也是为什么服务端每个 peer 的 AllowedIPs 必须写 `/32`：
写成 `/24` 意味着该 peer 可以伪装成同子网任意 IP，是安全漏洞。

## 客户端扩展点的固定顺序

添加新客户端遵循 5 步流水线，步骤顺序是硬约束：

```
① 生成客户端密钥对（独立，不依赖其他步骤）
② 追加 [Peer] 到 /etc/wireguard/wg0.conf（需要 ① 的公钥）
③ systemctl restart wg-quick@wg0（应用 ②）
④ 生成客户端 .conf（需要 ② 中服务端的公钥 + ① 中客户端的私钥）
⑤ qrencode 打印二维码（需要 ④ 的 .conf）
```

关键点：客户端的 `[Peer]` 段引用服务端公钥，所以客户端 `.conf` 必须在服务端配置确定后才能生成。
如果先写客户端配置再改服务端公钥，客户端配置即刻失效。

## PersistentKeepalive 与 NAT 老化

WireGuard 在无流量时完全静默，不发送任何包。这在公网环境下没有问题，
但在 NAT 后的设备上会导致 UDP 映射老化，服务端无法主动联系客户端。

`PersistentKeepalive = 25` 让客户端每 25 秒发一个空包维持 NAT 映射。
这是 WireGuard 唯一的 keepalive 机制——没有「服务端保活客户端」的选项，
因为 WireGuard 的对称设计中，双方都是"peer"。

适用场景：
- 手机（4G/5G，运营商级 NAT 老化通常 < 60s）
- 家庭宽带（NAT 老化时间因运营商而异）
- 任何 NAT 后的设备

不适用场景：
- 服务端（有公网 IP，端口可从外部访问）
- 全部在同一交换机下的纯局域网场景

## 密钥安全模型

```
      服务端                         客户端
  ┌──────────┐                  ┌──────────┐
  │ 私钥 S_s │ ← 留着别动        │ 私钥 C_s │ ← 每设备唯一
  │ 公钥 S_p │ ──→ 给客户端      │ 公钥 C_p │ ──→ 给服务端
  └──────────┘                  └──────────┘
        ↑                             │
        └─── 双方互存对方的公钥 ───────┘
```

- 私钥永不离开所属设备
- 服务端持有：自己的私钥 + 所有客户端的公钥
- 客户端持有：自己的私钥 + 服务端的公钥
- 客户端之间不交换密钥（hub-spoke 模式，所有流量经服务端中转）
