# 许可证替换与回退

## 授权文件与生效状态

Perforce 从 **`P4ROOT/license`** 读取无扩展名许可证，不是从程序目录或下载目录读取。
使用用户提供的文件并原样保留内容；本流程只负责部署和验证，不生成或修改许可证签名。

文件摘要只证明复制一致；重启后的 `p4 info` 才证明服务器实际接受了哪份授权。
安装前检查但不要回显签名值：

| 文件字段 | 用途 |
|---|---|
| `Customer` | 与重启后的客户名称对应，区分同额度的不同许可证 |
| `Users` | 与服务器识别的用户数对应 |
| `IPaddress` | 与当前目标 IP/实际服务器报告对应 |
| `License-Expires` | 授权期限；数字时间戳按 epoch 解读，实际展示以服务器输出为准 |
| `Support-Expires` | 支持期限，与授权期限分别核对 |
| `License` | 敏感签名值；不粘贴到文档、结果或版本库 |

签名有效性、版本/期限限制等最终以服务器的接受结果为准，不能只根据文件字段宣布成功。

## 替换事务

1. 显式连接目标 endpoint，确认 `serverRoot`、服务身份及当前许可证摘要。
2. 计算源文件 SHA-256；记录预期 customer/users/IP/期限，不记录签名。
3. 若目标已有 `license`，复制为唯一的 `license.before-<timestamp>`，核对备份哈希和读权限。无旧文件则记为“原无许可证”。
4. 正常停止服务并等待 Stopped；停止失败时不覆盖文件。
5. 在尝试写入前记录“目标可能已变更”，然后原样复制源文件到 `P4ROOT/license`，核对源/目标哈希。
6. 保持目录继承 ACL，确认服务账户能读取新文件；启动并等待 Running。
7. 检查实际监听与 `p4 info`，然后用独立认证连接执行 `login`、`login -s`、`depots`。
8. 客户名称、额度、IP、期限和认证均匹配后，才报告“新许可证生效”。保留旧备份路径供人工回退。

把“目标可能已变更”置于复制之前，是为了让部分复制失败也进入回退；不仅处理复制成功后的启动失败。
即便安装脚本返回 0，也应从外部重新查询一次服务/协议，避免把控制脚本状态当成业务结果。

## 失败回退

| 失败前状态 | 回退动作 | 验证 |
|---|---|---|
| 有旧许可证 | 停服务，恢复准确的备份 | 备份/目标哈希一致；旧授权摘要；认证访问 |
| 原无许可证 | 停服务，仅移除本次安装的目标文件 | 确认原无授权状态与服务可用性 |
| 目标出现并发修改 | 不覆盖未知新文件 | 报告冲突，等待确认 |
| 服务无法恢复 | 保留文件、日志和结果 | 明确报告未恢复，不能称替换成功 |

不要因许可证问题删除数据库、改 serverID、迁移 IP 或修改许可证字段。
回退只覆盖本次授权文件变化，不触及 depot、journal、checkpoint 或其他服务设置。

## 验证字段

CLI 使用显式目标和字符集：

```powershell
& $p4 -p $endpoint -C utf8 -u $adminUser -c setup-validation info
```

在 P4Python 的 `run_info()[0]` 中关注：

```text
serverRoot
serverVersion
serverID
serverLicense
serverLicense-ip
```

已验证的 2024.1 输出形状：

```text
Server license: <customer> <N> users (support ends YYYY/MM/DD) (expires YYYY/MM/DD)
Server license-ip: <bound-ip>
```

不要仅断言 `<N> users`：两份不同许可证可能有相同用户数。检查客户名/IP/日期，并结合安装文件哈希与服务重启证据。
不同版本或许可证类型缺字段时保留原始非敏感摘要并按实际格式核对，不伪造缺失字段。

结果只输出：源路径、目标路径、备份路径、哈希、服务状态、非敏感授权摘要、认证是否通过、回退状态。
凭据与许可证本体留在本机受限目录；不复制进 skill、测试夹具或 Git。
