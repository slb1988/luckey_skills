# Perforce Server 安装与验证

## 范围与交付

面向 **Windows 原生独立服务**，不默认迁移已有数据库、卸载 P4V 或修改远端服务器。
服务组合与许可证替换已在 `P4D/NTX64/2024.1/2596294` 验证；其他版本重新确认安装器格式、参数和输出。

交付：服务名/状态、自启方式、连接地址、程序与数据路径、认证资料的安全保存位置、许可证摘要、测试范围。
不在回复、日志或仓库中写密码、ticket、许可证签名值。

## 系统关系

| 对象 | 职责 | 验证依据 |
|---|---|---|
| `p4d.exe` | 数据库初始化、离线维护、版本查询 | 实际二进制 `-V`，不以安装包文件名或外层版本号代替 |
| `p4s.exe` | Windows SCM 管理的服务程序 | 服务 ImagePath、账户、状态及实际监听 PID |
| `p4.exe` / P4Python | 客户端连接 | 显式指定 port/user/charset；与服务端参数分离 |
| `P4ROOT` | `db.*`、server.id、license 等实例数据 | `p4 info` 的 `serverRoot` |
| 服务启动参数 + `set -S` | 此服务的 root/port/log/journal | 二者保持一致，避免维护时出现两套配置 |
| 防火墙规则 | 网络准入，不负责用户认证 | 地址、程序、端口、Profile、来源网段共同生效 |
| `P4ROOT/license` | 服务器读取的授权文件 | 重启后的许可证摘要，而不只是文件复制成功 |

## 先确定边界

- 确认目标 Windows 主机、安装包、数据目录、服务名、IP/端口、访问范围。
- 检查现有服务、监听、P4V/DVCS 和数据库；有数据/服务时停止“新装”流程，先确认升级或迁移范围。
- 记录现有客户端设置、二进制身份及待恢复的注册表值；只记录摘要，不输出凭据。
- 未明确要求远程访问时先绑定回环；指定 IP 后仅绑定实际属于本机的地址。
- 数据初始化和管理员引导保持回环可见；认证配置完成后再对指定网络开放。
- 用户未确认 UAC、安装进程未结束、服务未验证，都不能报告成功。

## 流程

### 1. 安装与服务配置

读取 [Windows 安装与服务配置](references/windows-install.md)。

1. 验证安装包和提取出的服务端程序签名；用 `p4d -V` 确认实际版本。
2. 优先使用受支持的安装器路径；若它因已装 DVCS 拒绝共存，不卸载客户端或伪造检测结果。
3. 独立部署分支：从已验证安装包取出服务端文件，放入独立程序目录；不覆盖现有 `p4.exe` / P4V。
4. 新建独立数据目录和日志目录；仅对全新、未运行的实例执行 Unicode 初始化。
5. 提权注册自动启动服务，配置服务账户和目录 ACL，显式设置 root/port/log/journal。
6. 检查运行状态、监听地址和 `serverRoot`，再进入认证引导。

### 2. 认证与网络

读取 [客户端隔离与分层验证](references/auth-and-validation.md)。

- 先创建管理员、强密码、保护表，配置 `security=3` 与 `dm.user.noautocreate=2`。
- **进程隔离不等于注册表隔离**：Windows 新实例在 `security=0` 时设密码，即使用 P4Python，也可能写客户端全局 `P4PASSWD` 缓存。操作前保存准确旧值/类型/是否存在，操作后验证并恢复本次影响。
- Unicode 客户端用命令级 `-C utf8` 或连接级 `charset='utf8'`，不改全局 `P4CHARSET`。
- ticket 和凭据文件使用仓库外的受限目录；不要覆盖现有连接的 ticket 文件。
- 停服务后同步修改显式启动参数与服务级 `P4PORT`，重启，再添加最窄的防火墙规则。
- 不将 LAN 访问需求扩大为公网/VPN/所有网卡；跨不可信网络需另行配置 TLS。

### 3. 安装或替换许可证

读取 [许可证替换与回退](references/license.md)。

使用用户提供的文件；备份旧文件 → 停服 → 原样复制为 `P4ROOT/license` → 比对摘要 → 启动 → 检查实际授权及认证访问。
若失败，恢复旧文件或原无许可证状态，再验证恢复结果。不要把“回退后能用”报告为新许可证生效。

### 4. 验收

| 层级 | 至少检查 | 不能推出 |
|---|---|---|
| 服务 | Running、自启、服务账户、实际 PID | 程序没有立即退出 ≠ P4 已可用 |
| TCP | 目标地址/端口的连接 | TCP 成功 ≠ 正确实例、认证或授权成功 |
| 协议 | `p4 info` 的 root/version/serverID | `info` 成功 ≠ 密码有效 |
| 认证 | `login`、`login -s`、`depots` | 不能只检查默认客户端的旧 ticket |
| 许可证 | customer/users/expiry/IP 与本次目标一致 | 文件哈希一致 ≠ 服务器接受许可证 |
| 持久运行 | 重启后重复连接和认证测试 | 服务重启测试 ≠ 已进行系统重启测试 |
| 网络范围 | 本机 IP 测试与异机测试分开标注 | 本机访问 LAN IP ≠ 异机穿过防火墙 |

收尾检查本次目标服务器的 `opened -a`。只做安装/查询不应留下测试文件或工作区变更；不操作原远端项目的 CL。
正常证据齐全即停止，不为文档验收再次重启生产实例。

## 汇报模板

```text
服务：名称 / Running / Automatic
连接：明确的 IP:port；是否启用 TLS
目录：程序目录、P4ROOT、日志目录
认证：管理员名、受限凭据文件位置（不展示密码）
许可证：未安装 / 客户、用户数、到期日、绑定 IP
验证：TCP、协议、认证、重启；本机 / 异机范围
回退：如有旧许可证备份，列出路径；失败时说明恢复是否完成
保留项：原 P4V/默认连接/全局字符集是否保持原值
```
