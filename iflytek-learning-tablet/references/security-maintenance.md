# 安全边界与维护

## 已观察到的状态，不夸大为漏洞结论

采样固件 `iFLY_V1.05.9` / Android API 32，以下是只读上报值与通信实验：

| 证据 | 可以得出的结论 | 不能直接得出的结论 |
|---|---|---|
| `getenforce=Permissive` | 当前 SELinux 不在 Enforcing 模式，强制访问控制防线较弱 | 已被入侵、任何文件均可读取；Linux DAC/其他限制仍可能生效 |
| `ro.boot.verifiedbootstate=orange`、`ro.boot.flash.locked=0` | 启动链上报解锁相关状态 | 所有同型产品出厂均如此、知道是谁何时解锁 |
| `ro.crypto.state=unsupported` | 系统没有通过该属性声明常规加密状态 | 已证明所有磁盘内容都不加密；未做离线介质验证 |
| `ro.debuggable=0`、build type user | 非标准 userdebug 配置 | 网络 ADB 一定关闭 |
| ADB shell 为 UID 2000；管家本机命令为 UID 10088；PATH 未发现 su | 两种入口实测都不是 root，未验证可用 root 接口 | 整机绝无提权入口；不要试 root 来“验证” |
| 安全补丁上报 2022-06-05；WebView 94.0.4606.71 | 补丁/浏览器内核基线较旧，需要纳入更新评估 | 具体 CVE 已可利用；未进行漏洞利用测试 |
| 新建无 cookie 的 HTTP 客户端能调用 `/cmd` 并取回结果 | 采样环境中 Web 命令接口未要求该客户端登录，属于敏感局域网管理面 | 公网可达或所有版本都无认证 |
| Mac 直接连接成功，没有本轮输入口令 | 当前 Mac 可发送 ADB 指令 | 任意陌生主机都能跳过认证 |

用户提到的猜测口令不保存在 Skill/脚本里；本链路没有使用它，也未通过试密码恢复连接。

## 默认安全操作

1. 只在用户控制、可信的局域网内使用网络 ADB 与 Web 管理；不添加公网转发，不向公共网络开放 9898 或 ADB 端口。
2. 页面里的普通 shell/ADB shell 不是同一种权限。先 `id`，不因按钮说明提到 root 就假定已 root。
3. 调试结束可建议用户从原管理入口关闭不需要的 Web/无线调试服务，但关闭会中断当前连接，先等确认，不自动执行。
4. 不复制 `adbkey`、设备配对私钥或应用凭据；需要新增电脑授权时走设备提供的正常授权/配对流程。
5. 不把串号、包含水印的原始屏幕、应用私有数据和完整系统日志发布到共享 references。

## 更新与恢复

- **先识别版本**：保留 display ID、API、patch level、WebView provider 和关键应用版本。
- **更新前确认**：用户数据备份范围、厂商渠道、兼容性和回退条件；使用授权渠道，不根据包名就直接下载替换系统 WebView/OTA。
- **更新后复测最小集合**：实际 ADB 端口 → `shell id`；Web 命令前台生命周期 → 唯一标记输出；HOME 组件；WebView provider；用户关心的具体功能。
- 固定 TCP 端口、改持久属性、重启 adbd、禁用系统包都可能让唯一远程通道丢失；有本地恢复手段并得到授权后才能变更。

## 证据与知识保存

原始采集放工程忽略目录，如 `.local/iflytek-learning-tablet/<采样时间>/`。版本相关事实写对应 reference，并标清适用固件；不把当前 IP、端口、PID、剩余电量变成永久配置。

命令串退出码仅表示最后命令的结果；某些可选工具未安装/被拒绝时单独记录。采样中 `command -v su`、读取 `/proc/<adbd>/exe`、查询不存在的 APEX init 目录等未成功，不能一概包装成“所有检查通过”。

## 本基线的未验证项

- 重启、换网络后端口/授权是否保留，mDNS 未发现服务的内部原因。
- 属性 5555 与实际 ADB 监听不同步的固件内部实现。
- 未归属的另一个监听端口：不根据数字猜服务，也未做整机安全审计。
- bootloader 实际模式、离线磁盘加密、root 可用性；本次不进入 recovery/fastboot。
- 家长管理业务、OTA 升级、摄像头/麦克风功能、触控与笔的全量测试、温控压力测试。

这些边界不影响已确认的 Mac ADB 连接和命令桥使用结论。
